EMERALDOS GOLD 1M

Complete standalone E.L.S.U.S.-compatible release folder.

Gold 1M keeps the Windows 10-inspired Gold interface while making full VM continuity a required part of startup. The operating system does not permit cloud autosave until local and cloud migration have been merged and validated.

MIGRATED DATA
Gold 1M carries forward all available:
- Files and folders
- Settings and preferences
- Registry keys and history
- Clipboard history and startup apps
- User applications and verification state
- Custom application logos
- Gold Mail data
- Notes, tasks, events, contacts, tickets, and notifications
- Staff data, snapshots, Sticky Notes, voice recordings, update preferences, update history, and Focus Sessions

MIGRATION SAFETY
1. The preboot migration merges every known local Gold namespace.
2. Cloud autosave is blocked.
3. Gold 1M reads goldVM/current and every supported split schema, including Gold 1K and Gold 1L.
4. It scans goldVMData, version backups, legacy drive documents, alternate user-ID paths, and recoverable orphaned chunks.
5. Conflicting files are preserved with migration-safe IDs.
6. A migration report is written locally.
7. Only after validation is cloud autosave enabled.
8. Gold 1M writes version-specific category backups for future releases.

When cloud verification is temporarily unavailable, cloud autosave remains blocked instead of replacing older cloud data. Local applications remain usable and migration retries when the browser returns online.

SETTINGS UI
Gold 1M fixes navigation/content overlap, wide-control overflow, card collisions, toolbar overflow, and narrow-window behavior in Settings and related applications.

E.L.S.U.S. COMPATIBILITY
Gold 1M uses the original E.L.S.U.S. implementation from Gold 1I:
1. Read system/emeraldGoldLatest.
2. Ask the user before updating.
3. Save and validate the version-independent cloud VM.
4. Write emeraldGoldShell_pendingManifest locally.
5. Return to ../gold-shell.html?force=1.

PUBLISHING POLICY
Gold 1M never publishes during boot, login, migration, setup, update checks, or query-string processing. The shared Firestore version pointer is written only after Staff Edition and Emerald Mail verification, the correct publisher PIN, and a direct click on Publish this Version.

Upload this folder as EmeraldOS/Gold_1M/.
